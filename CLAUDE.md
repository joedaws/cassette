# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
cargo build                    # compile
cargo test                     # run unit tests
cargo run -- -t 10 -w 500      # run with 10-min timer and 500-word goal
cargo run -- -l 8              # run with 8 visible text rows per cassette
cargo run -- -T morning        # one cassette per topic from the 'morning' config template
cargo run -- --theme gruvbox   # themed session; `cassette themes` lists themes
cargo run -- new myjournal     # a new session aliased 'myjournal' (never resumes a same-named one)
cargo run -- today             # session aliased with today's date; same-day relaunches resume it
cargo run -- stats             # streak + weekly/monthly totals from the session store
cargo run -- find [text]       # list recent sessions newest-first, optionally filtered
cargo run -- resume            # load the most recently created session back into the TUI
cargo install --path .         # install `cassette` binary to PATH

# the session store: what the TUI above writes into, also reachable directly
cargo run -- session new --alias morning                  # create a session, print its id
cargo run -- session list                                 # sessions newest-first (no active session; this is how you recover an id)
cargo run -- writer register --name bot --kind agent      # register a writer identity
cargo run -- queue new "gratitude" --session <ID>          # add a cassette to a session's queue
cargo run -- queue next --session <ID> --json              # next open, unlocked cassette, machine-readable
cargo run -- queue write <ID> --session <ID> --side a      # replace (or --append to) one side, read from stdin
cargo run -- queue lock <ID> --session <ID>                # sticky-lock a cassette to yourself (human-only)
```

## Architecture

`cassette` is a Rust TUI freewriting app built on [ratatui](https://ratatui.rs) with crossterm as the backend. The user writes on one or more "cassettes", each displayed as a colored multi-line widget with a top-fade effect.

### Source layout

**`src/cassette.rs`** — `Cassette` is a cursor-zipper: text is split into `left` (before cursor) and `right` (after cursor); text may contain `\n`. Each cassette has two sides like a tape: the zipper always holds the active side, and `flip()` swaps it with the stored back buffer (`Side::A`/`Side::B`), so each side keeps its own cursor — and its own undo stack (`snapshot`/`undo`, capped at `UNDO_DEPTH`). Side B is a scratch pad; output writes side A under a `## Side A` heading always and side B under `## Side B` when non-empty, and `word_count` covers both sides. Each cassette has an optional `topic` label (shared by both sides) that appears in the separator and in the markdown heading (`# Cassette 1 — topic`). Basic ops (`insert`, `insert_str` — bracketed paste as one edit, `backspace`, `delete`, `move_left/right`, `delete_word_back`, `delete_to_line_start`) plus vim motions (`move_up/down`, `move_row_start/end`, `move_word_forward/back`, `move_text_start/end`, `delete_line`, `open_below/above`). Width-aware motions take the wrap width as a parameter. `from_sides` rebuilds a cassette from saved text for `resume` (side A active, cursor at its end, no undo history). `wrap_spans`/`pos_to_row_col` compute display rows (cell-width wrap via `char_width` — CJK/emoji count 2, combining marks 0 — hard break on `\n`) and are shared with `ui.rs`. Pure data model with no rendering logic.

**`src/app.rs`** — `App` holds all application state: the list of cassettes, focus index, terminal dimensions, timer, word goal, reel animation frame, editing `Mode` (`Insert`/`Normal`/`Topic` — `Topic` is a status-line prompt that captures `topic_input` for the focused cassette and returns to `topic_return`, the mode it was opened from), and `pending` prefix key for two-key sequences (`dd`, `gg`). `App::new` takes the store `session` id as its fourth argument — plain data here, since resolving or creating that session against a `Store` is `main.rs`'s job, not `App`'s; it is empty only in `-o` mode, which persists nothing. `apply_topics` seeds the session from a `-T` template: one cassette per topic, capped at `MAX_CASSETTES`. `record` (the `-R` flag) marks a forward-only session; `idle_secs`/`tick_idle`/`idle_nudge` drive the "tape's still rolling" hint, shown after `IDLE_NUDGE_SECS` quiet seconds in timed or record sessions only and reset by any keypress in `handle_key`. State transitions are plain `&mut self` methods with no I/O — no `Store`, no `LockGuard`, nothing that touches disk. `modify_focused` accepts a closure so callers in `main.rs` can apply any `Cassette` operation; it is the read-only gate too — when `App::read_only` is set (the focused cassette's lock belongs to another writer), it drops the edit on the floor instead of applying it, so a keystroke that can't be saved never reaches the buffer in the first place. Otherwise it marks that one `Cassette`'s own `dirty` flag, and `dirty_indices()`/`clear_dirty(idx)` let `session_writer.rs` flush exactly the cassette that changed rather than every cassette in the session. `load_cassettes` replaces the list with cassettes parsed from a resumed session's store files, focusing the last one and recording `baseline_words`; live stats (`session_word_count`, the goal check, `tape_ratio`, `format_stats`) count only words typed on top of that baseline, while `total_word_count` stays the session-total for the closing recap. Timer expiry and reaching the word goal `flash()` a transient status message (self-clears after `STATUS_FLASH_SECS` via `tick_status`) and request a terminal bell through the `bell` flag, which `main.rs` consumes — as is `suspend`, the one-shot Ctrl+Z suspend request. `merge_external(id, incoming, insert_at)` is how `main.rs`'s live sync lands another writer's changes: it finds the cassette by id (never by index — an insertion elsewhere in the list may have shifted one), and either replaces it in place with `incoming`'s text/topic/`locked_by` under the follow-if-at-end cursor rule (a cursor already at the end of the old text follows the new end; one that had wandered elsewhere stays put) or, when the id is unknown, inserts `incoming` as a new cassette at `insert_at` (capped at `MAX_CASSETTES`). A no-op short circuit skips the rebuild — and the cursor/undo reset it would cause — when text, topic, and `locked_by` all already match, so this process's own flush moving a file's mtime merges to nothing. Focus is always re-resolved by id afterward, so an insertion ahead of the focused cassette can never silently steal it. `busy_holder: Option<String>`, alongside `read_only`, names whichever writer currently holds a cassette this session failed to lock, for the TUI to show.

**`src/ui.rs`** — All ratatui rendering. `render` builds a vertical layout with one chunk per *visible* cassette plus the reel stats bar (drawn only when a word goal or timer is set: tape winds from the supply reel onto the take-up reel as `tape_ratio()` — words over the word goal, or elapsed time when only a timer is set; `tape_ratio()` is `None` and no bars render without either), a vim-style info line (mode, ln/col, char count, cassette i/n — overridden by `status_msg`), and help row; the reel/info/help footer is pinned to the bottom of the window by a `Min(0)` filler between it and the cassette stack (the closing `─` separator stays directly under the stack and carries the ↓ overflow hint). Cassettes can exceed the screen (up to `MAX_CASSETTES`, 36): `App.cassette_scroll` is the first visible cassette, `ensure_focus_visible` keeps the focused one in the window, and separator rows show "N more ↑/↓" hints for cassettes scrolled out of view. The focused cassette renders full-height on the terminal's default background with a line-number gutter (`GUTTER_WIDTH` cols, `~` on rows past the end); its viewport scrolls typewriter-style (cursor row centered, clamped at the ends) and rows fade with distance from the cursor row via `DIM`/`DarkGray` steps, so the bright band follows the cursor even when the scroll clamp leaves it off-center. Unfocused cassettes are minimized to their last line (colored background, line number shown) — including one that just appeared because another writer created it, or whose text just changed because another writer wrote it; `render` has no special case for either, since `App.cassettes` already reflects it by the time a frame draws. In insert mode the cursor is a dedicated `REVERSED` bar cell (`│`) between left and right; in normal mode it's a `REVERSED` block overlaid on the char under the cursor (a space at line ends), so columns stay true — the text may reflow by one cell on mode switch. A reached word goal styles the stats green+bold, winning over the expired-timer red. `info_text` checks `status_msg` before the mode line, so a busy cassette's holder is actually named on screen by the persistent message `main.rs`'s `try_acquire` leaves in `status_msg` — `LockError::Busy`'s own `Display`, `'<id>' is held by <holder> (since <time>)` — not by `info_text`'s own read-only branch; that branch (`-- READ ONLY (open by <holder>) --` when `app.busy_holder` is set, the bare `-- READ ONLY --` 5a left otherwise) is reachable only while `status_msg` is empty, e.g. the single frame right after a startup acquire failure, before the first tick's `retry_lock` fills both in. `render_separator` builds its tag/label spans from `separator_pieces` (side tag, then topic label if set, then a sticky-lock label if set) so production and the `#[cfg(test)]` `separator_text` helper can never disagree about content; the sticky label — `╡ locked by <holder> ╞`, same bold-no-color style as the topic label — is worded deliberately unlike the busy status message's "is held by": busy is a live writer's lock that frees itself, locked is a durable `queue lock` claim only a human can clear.

**`src/main.rs`** — Terminal setup/teardown (raw mode, alternate screen, bracketed paste), a panic hook + `catch_unwind` so the terminal is restored and the session saved even on error/panic, unix signal handling (`signal-hook` flags polled by the event loop: SIGTERM/SIGHUP quit through the normal save path; SIGTSTP or the Ctrl+Z binding run `suspend_session` — flush the focused cassette through the guard `session_writer` holds, restore the terminal, raise SIGSTOP, re-enter raw mode + redraw on SIGCONT), the crossterm event loop (`Event::Paste` → `handle_paste`: newline-normalized, one undo snapshot, topic prompt joins lines), modal key dispatch (`handle_key` → `handle_insert_key`/`handle_normal_key`/`handle_topic_key`; topic mode owns the keyboard so Tab/flip can't move the prompt off its cassette; in record mode `handle_insert_key` accepts only chars and Enter — no deletions, movement, or Esc), the unknown-`-T`-template and unknown-`--theme` exits (both code 2; flag parsing itself lives in `cli.rs`), and `session_summary` — the words/duration/wpm recap (plus per-cassette breakdown) printed to stderr after every non-empty session; a resumed session reports `N new words … (M total)` and prints nothing when no new words were added.

`resolve_session` decides, before the terminal is touched, which store session this launch writes to and whether this run created it, per the entry-point table in its own doc comment: a bare `cassette` or `new <NAME>` always creates a fresh session (`<NAME>` becomes its alias — never a lookup that resumes a same-named one), `today` opens the session aliased with today's date or creates it, `resume [NAME]` opens the newest session, or the newest carrying that alias — falling back to `NAME` as a **session id**, so an id `cassette find` printed reopens the session it names (aliases are still checked first; 4b's "ULID only, an alias never resolves" governs `--session` on the queue commands, not this human entry point), and `-T <template>` creates a fresh session seeded with one cassette per topic. Two combinations are refused rather than half-honoured: `-T` with `resume`, or with a `today` whose day already has a session (`load_cassettes` would replace everything `apply_topics` built, silently discarding the topics), and `-o` with `resume`/`new`/`today` — `-o` persists nothing and so names no session, and silently dropping a subcommand the user typed is the one outcome to avoid. `load_session_cassettes` reads an opened session's cassettes back in queue order via `Store::scan_session`, splitting each body on `queue::json::split_sides` — the inverse of `output::cassette_body` — and lands them in the app through `App::load_cassettes`.

Once the app exists, a `session_writer::SessionWriter` is opened against the resolved session (skipped entirely in `-o` mode, which persists nothing) and `create_missing_cassettes` mints a store cassette for every cassette on screen — the template-seeded ones and the bare launch's single empty one alike — before `acquire` takes the focused cassette's lock. If that acquire fails, the app opens **read-only** (`app.read_only = true`) rather than refusing to start: refusing would let a running agent lock a human out of their own session, and starting anyway would silently drop keystrokes with no guard to write them through. `run`'s event loop calls `follow_focus` after every keypress to restore the two store invariants a key can break — mint a store counterpart for a `Ctrl+N` cassette, and move the held lock when focus moved (flushing the outgoing cassette through its guard before dropping it) — and flushes the focused cassette through `flush_focused` every `AUTOSAVE_SECS`, which must never call `Store::lock` since a second acquire of a lock this process already holds reports `Busy` against itself. `try_acquire(app, w, idx)` is the one place a lock attempt's outcome is recorded — `read_only`, `busy_holder` (via `busy_holder_name`, read straight off the lock anchor's own `Attribution`, the same source `queue write`'s exit-3 message uses), and the persistent `status_msg` banner, cleared again on a successful retry — so `follow_focus`'s per-keypress retry and `retry_lock`'s per-tick retry can never disagree about what a failed acquire looks like on screen. Once a second, `retry_lock` re-tries the focused cassette's lock when the session is already read-only (so a human who steps away from a busy cassette finds it editable on return without typing a character to discover it), and then — before that tick's autosave — `sync_external_writes` notices what other writers did to the *unfocused* cassettes: a cheap stat-only pass over the session's `cassettes/` directory decides what changed since the last tick, and only a changed id is read, parsed, and handed to `App::merge_external` at its queue-order position (`Store::scan_session` supplies the order) — skipping the cassette this process holds (nobody else can have written it) and any newcomer once `MAX_CASSETTES` is already on screen. On the way out, `writer.finish()` does the final flush-then-release and removes a session this run created if neither the app nor the store holds anything in it, before `session_summary` prints its recap.

**`src/session_writer.rs`** — the TUI's half of the store protocol: `SessionWriter` is the TUI's only caller of `Store::lock` (the queue commands in `src/queue/{write,edit}.rs` are the others, one per mutation), and everything it writes goes through the `LockGuard` it holds — never a bare `std::fs::write`. **Focus means held**: `acquire(app, idx)` takes and keeps the lock for cassette `idx` from the moment it is called until a different index is acquired or `finish` runs; there is no idle timeout and no reacquisition, since `flock` is per-open-file-description and a second acquire of a lock this process already holds would report `Busy` against itself (guarded by a `debug_assert!` and skipped outright when the requested index is already held — `Store::holds` answers "do *we* hold it" from in-process bookkeeping rather than by probing the anchor). Moving focus flushes and drops the outgoing guard, through the guard, before taking the new one — dropping first would either lose the text or force a re-acquire `flock` may refuse. **Every acquire re-reads**: the instant the lock is won, `refresh_from_disk` reads the cassette back and adopts the disk's body and topic when they differ from memory — the other half of the parent spec's invariant 1 ("every cassette you do not hold, you re-read from disk"). While a cassette is unfocused the TUI holds nothing and an agent may `queue write` it; without the re-read, one keystroke after tabbing back republished the stale in-memory copy over the agent's words, reverted `last_writer`, and warned nobody. This is the same job `main.rs`'s `sync_external_writes` does for every *other* cassette on a tick — `refresh_from_disk` is just its equivalent for the one cassette this process is about to hold, run synchronously inside `acquire` rather than waiting for the next tick — and it resolves a sticky `locked_by` id to a display name the same way, via `store::writers::display_name`. Nothing is lost either way: an unfocused cassette can never be dirty — `modify_focused` only touches the focused one and `acquire` flushes the outgoing cassette before the guard moves — and an unchanged file is skipped outright, so an ordinary Tab away and back keeps the cursor, the undo stack and the active side. `flush_focused`/`flush_held` write only when the held cassette is `dirty`, re-reading its frontmatter under the lock first and replacing only the fields the TUI owns (`topic`, `last_writer`, `updated_at`) — `priority`, `status`, and `locked_by` belong to the queue commands, so an autosave can't undo a concurrent `queue move`/`close`/`lock`. `create_cassette`/`create_missing_cassettes` mint a store cassette (id, tail-of-queue priority) for any in-memory cassette that doesn't have one yet — `Ctrl+N`'s pure key handler can't reach a `Store`, so `main.rs`'s event loop calls this afterwards to restore the invariant. `finish` does the final flush-then-release and, only for a session **this run created**, removes the session directory if `App::is_empty()` *and* `store_is_empty` agree nothing is there — the latter re-scans the store rather than trusting `App`'s memory, because a concurrent agent's `queue new`/`queue write` on the same session is invisible to `app.cassettes` and `remove_dir_all` would take its words and live lock anchor with the directory. A cross-process test spawns the real `cassette` binary's `queue write` against a lock this module holds in-process, rebuilding the binary itself first (`bin_path()`) since `cargo test --bin cassette` alone would not.

**`src/cli.rs`** — clap v4 derive parsing, the only place the command line is read. `Cli` is the clap tree; `into_args` lowers it to `Args`, the flat struct `main()` consumes (minutes → `timer_secs` in seconds is the one conversion). **Every mode is a subcommand and there is no top-level positional** (`new <NAME>`, `today`, `resume [FILE]`, `stats`, `find [TEXT…]`, `themes`); global options (`-t -w -l -T --theme -R -o`) parse before or after the subcommand. That shape is load-bearing, not cosmetic: a positional coexisting with subcommands is ambiguous, and clap resolves it by silently discarding one side — `cassette mynote today` used to drop the name, and `args_conflicts_with_subcommands` made `cassette -t 10 today` write a note called "today". Removing the positional deleted both workarounds, so add new modes as subcommands. Bad input exits 2 through clap itself; there is no hand-written validation. `find` deliberately avoids `trailing_var_arg` so `find foo -t 10` doesn't swallow the flags into the query.

**`src/stats.rs`** — the `cassette stats` action: `scan_store` reads every session in the `Store` into one `NoteMeta` (`date`, `words`) — the day from `session.toml`'s `created` (RFC3339 UTC, read back in local time), the words summed across the session's cassettes via `session_word_count` (which counts the same way `Cassette::word_count` does, so the TUI and this command never disagree about a session's length) — plus the total count of cassette files across all sessions that couldn't be read or parsed, returned alongside the metas so `render` can append a trailing `N unreadable` line rather than silently under-counting. A session whose `created` timestamp fails to parse is skipped, same as `Store::list_sessions` skips an unparseable `session.toml`. `render` prints streak (consecutive days, tolerant of an unwritten today), this-week (Monday start) and this-month notes · words, and totals. The legacy notes dir is deliberately not consulted: `scan_store` is the only source, so notes written before this move are no longer counted here (see the design's decision 7) — they are untouched on disk, just invisible to this command now. Pure functions over `&Store` — `main.rs`'s `args.stats` branch is the one place a scan result becomes printed output.

**`src/find.rs`** — the `cassette find [TEXT…]` action: `scan_store` builds one `NoteEntry` per session in the `Store` — its id as the openable `path` (`cassette resume <id>` takes it verbatim), its date from `session.toml`'s `created`, words summed the same way `stats.rs`'s `session_word_count` does, topics collected from every cassette's `meta.topic` in queue order, and a preview (`first_body_line`, truncated to `PREVIEW_CHARS`) drawn from the highest-priority cassette — plus the same `unreadable` count `stats.rs` returns, for the same reason: a damaged cassette must visibly under-count, never silently. `render` prints the newest-first listing (capped at `MAX_LISTED`, 10, with an `… N more` hint and a `resume` footer), filtered by the query words joined into one case-insensitive substring match over everything a row can print — the session id, its alias, its topics and every cassette's body, assembled by `build_haystack`, which `scan_store` and the unit fixtures share so a fixture can never test a shape the scanner does not produce. The legacy notes dir is deliberately not consulted, same as `stats.rs` — see the design's decision 7. Same shape as `stats.rs`: pure functions plus a thin `scan_store`.

**`src/theme.rs`** — `Theme` (resolved ratatui colors: optional focused `text`/`background` — `None` means terminal defaults — plus `unfocused_bg`/`unfocused_fg`, per-side `accent_a`/`accent_b`, and `help_key`/`help_text` for the help line, whose key combos render bold in `help_key` and descriptions in `help_text` via `ui::help_line`) and `ThemeSpec` (the config-file form: optional color strings, `"#rrggbb"` or ANSI names via `parse_color`). `builtins()` ships default, dracula, gruvbox, nord, solarized-dark/-light. `resolve(name, user_themes)` looks up user `[themes.<name>]` specs first — a spec overrides the same-named built-in field-by-field, or extends the default look for new names — then built-ins; theme selection is config `theme = "…"` overridden by `--theme`. `all()` builds the `themes` listing.

**`src/output.rs`** — the flat-note writer Phase 5a moved the TUI off of, kept (`#![allow(dead_code)]`) rather than deleted because Phase 6 is what removes the flat-note format outright; `write_markdown`, `parse_markdown`, `parse_append_base`, `write_markdown_appended`, `is_draft`, and their frontmatter helpers have no non-test caller any more. The one item here with a live caller is `cassette_body(c: &Cassette)`, the store-shaped body builder: `## Side A` always, `## Side B` only when it has text, and no `# Cassette N` heading (that wrapper belonged to the old one-file-per-session format and would leak into `json::split_sides`, which folds anything before the first `## Side A` into side A). It delegates to `queue::write::build_body` rather than re-deriving the shape, because `queue write` and the TUI write the same files and a cassette's body must not depend on which of the two touched it last — a test pins the two byte-identical across the shapes that differ (trailing newlines, an empty side B, a re-emitted one).

**`src/config.rs`** — `config::load_config` returns `Result` — a config file that exists but doesn't parse exits 2 with the TOML error — and `config::config_path` resolves `$XDG_CONFIG_HOME/cassette/config.toml` falling back to `~/.config/cassette/config.toml` on every OS (never `dirs::config_dir()`, which would be `~/Library/Application Support` on macOS). `Config::notes_dir` and `default_notes_dir` are the same kind of deliberately-kept dead code as `output.rs`'s flat-note writer: `stats` and `find` moved to reading the session store, so nothing reads either any more, but an existing config file that still sets `notes_dir` continues to parse rather than erroring. `daily_format` (chrono strftime, default `%Y-%m-%d`) now names the alias `cassette today`'s session resolution looks for and creates, not a filename. `max_open` caps the cassettes one session may hold open for `queue new`/`queue reopen`, defaulting to `store::MAX_OPEN` when unset; the TUI enforces its own, separate cap (`App::MAX_CASSETTES`, 36) and does not consult this key — `session_writer::create_cassette` mints a store cassette for whatever the pure key handlers already put on screen.

**`src/queue/{mod,view,write,edit}.rs`** — the `cassette queue` commands, split on the lock boundary `mod.rs`'s module doc declares: `view.rs` holds the read-only commands (`list`, `show`, `next`) and is provably lock- and write-free — no `guard.write(`, no `atomic_write(`, no `std::fs::write(` anywhere in the file; `next` walks queue order (`store::priority::queue_order`) filtering `Status::Open` cassettes with no sticky `locked_by` claim, then probes each via `Store::is_free` (acquire-and-release within one call, never held past a return) to skip busy ones, distinguishing `Busy` (open, unlocked cassettes exist but every one's flock is currently held, exit 3) from `Empty` (nothing open and unlocked at all — including a queue that is entirely sticky-locked, exit 5). `write.rs` holds `write`, the one command that mutates a cassette body — deliberately the only code path that acquires a lock and THEN reads stdin, an order the cross-process tests in `tests/lock.rs` depend on for determinism — and `write_permitted`, which an agent fails with `Sticky` (exit 4) against a cassette someone else's `queue lock` claimed; a human is never blocked by it. `edit.rs` holds `new` (mints a fresh id and priority, checked against the session's `max_open` cap before anything is written — `Full`, exit 6), `close`/`reopen` (each takes the cassette's lock; `close` additionally runs `close_permitted` against a sticky `locked_by` claim — an agent may not close over one, `Sticky`, exit 4), `lock`/`unlock` (`queue lock`/`queue unlock`: human-only — an agent invoking either is `Usage`, exit 2, not `Sticky`, since it has misused the CLI rather than met a claim to escalate over; both are idempotent no-op-and-exit-0 against their own no-op case — locking your own existing claim, or unlocking an already-unlocked cassette — matching the pattern 4b's close-on-closed should have set; locking a cassette a *different* writer holds is `Sticky`, exit 4, while `unlock` always succeeds regardless of holder, since any human may clear any claim), `move_cassette`/`target_priority` (the placement arithmetic for `queue move`, split into an id-carrying `MoveAnchor` the CLI produces and an id-free `MoveSide` the pure arithmetic takes), and `renumber_all` (fresh sparse priorities for a whole session; the one caller of `Store::lock_many`, and it must be called holding no locks — flock is per-open-file-description, so a caller already holding one of the session's guards would deadlock against itself). `mod.rs` carries what all three share: `QueueError` (`Usage`/`Busy`/`Sticky`/`Empty`/`Full`/`Io`, mapped in `main.rs` to exit codes 2/3/4/5/6/1) and `WriterSource` (`Flag` — from `--writer` or `$CASSETTE_WRITER`, where an unknown name is a usage error rather than silently spawning a second, privileged `human` identity — versus `Env`, from `$USER`, which bootstraps a new writer on first use).

**`src/queue/json.rs`** — the `--json` contract types and the body splitter, kept pure (no `Store`, no `std::fs`, no locking) so the frozen wire shape is checkable by reading this file's imports alone: `SessionRef`, `WriterRef`, `CassetteView` (mirroring a cassette plus derived `busy`, `waiting_on`, `side_a`/`side_b`), and `Listing` (a session's cassettes plus `unreadable`, the same count the prose listing shows) are the `Serialize` types `queue list`/`next`/`show` emit. `status`, `kind`, and `waiting_on` are frozen `&'static str` wire spellings (`"open"`/`"closed"`, `"human"`/`"agent"`) rather than derived from `store::meta::Status`/`store::writers::Kind` via serde's enum serialization, so a later Rust-side rename can't silently change what an agent parses. `split_sides` divides a cassette body into `(side_a, side_b)` on the `## Side A`/`## Side B` headings `output::build_body`/`queue::write::build_body` write, folding any preamble into `side_a` rather than dropping it, and treating a body with no headings at all (a hand-edited file, or one from before either writer existed) as all `side_a`. `count_words` matches `Cassette::word_count` exactly so the TUI and the JSON contract never disagree about length; `waiting_on` is the inverse of the last writer's kind, `None` when that writer can't be resolved against `writers.toml` — emitting `null` rather than guessing whose turn it is.

**`src/session.rs`** — the `cassette session new|list|alias` commands: pure functions over `&Store`, with `main.rs`'s `run_session_cmd` the one place that turns their `Result` into an exit code. Sessions are named by ULID only; an alias (`session new --alias`, `session alias <ID> <ALIAS>`) is a display label shown in `list` and nowhere else — it never resolves in place of an id, so there is no uniqueness rule on it and no id-prefix matching anywhere in this module, on purpose. `new_session` creates a session and returns its id; `list` renders newest-first (capped at `DEFAULT_LIST_LIMIT` — 15 — unless `--all`, ties broken by id so the order is total) and says how many rows it hid rather than dropping them silently; `set_alias` treats an unknown session id as a usage error (exit 2), distinct from an I/O failure (exit 1) — `SessionError` is shaped like `queue::QueueError` minus `Busy`, which no session command can ever produce since none of them contends a lock.

### Key bindings

- Both modes: Tab/Shift+Tab switch cassettes, Ctrl+N new cassette, Ctrl+T topic prompt (returns to the mode it came from), Ctrl+B (or Shift+Enter on kitty-protocol terminals) flips the cassette to its other side, Ctrl+Z suspend (flushes the focused cassette through its held guard first; raw mode swallows the tty's own TSTP so this is an explicit binding), Ctrl+C quit. The active side is always tagged in the separator (`╡ SIDE A ╞` in the loud accent — yellow by default — `╡ SIDE B ╞` in the calm one — dark gray; `╡ A ╞`/`╡ B ╞` on minimized cassettes) and in the info line (`· side A`/`· side B`); the line-number gutter carries the same per-side accent. A set topic follows the side tag as a bold `╡ topic ╞` label.
- Insert: type to write, Enter for newline, Ctrl+W deletes the word before the cursor, Ctrl+U deletes to line start, Esc → normal mode.
- Normal (mini vim): `h j k l`, `w b`, `0 $`, `gg G`, `x`, `dd`, `u` (undo; entering insert mode snapshots so one `u` undoes the whole typed burst), `i a I A o O`, `t` opens the topic prompt (Enter commits, blank clears, Esc cancels), `q` quits.
- Record mode (`-R`, opt-in): chars and Enter only — deletions, cursor movement, and normal mode are disabled; flip/topic/cassette switching still work; quit with Ctrl+C. Info line shows `-- RECORD --`.

### Conventions

- `App` and `Cassette` are pure: no I/O, no ratatui types. Keep rendering in `ui.rs` and I/O in `main.rs`.
- The cursor is stored implicitly as the split between `left` and `right`; `cursor_pos()` is `left.chars().count()`.
- Wrapping is word-boundary (`wrap_spans`) and counts terminal cells, not chars (`char_width`): overflowing words move whole to the next row, the space stays trailing on the previous row (wrapped rows never start with a space), words longer than the width hard-break, and trailing space runs hang past the edge. Width comes from `cassette_width()` (terminal width − 2 − `GUTTER_WIDTH`); in insert mode the cursor bar occupies one display cell in the wrap calculation. `j`/`k`/`0`/`$` operate on display rows; `dd`/`o`/`O` operate on logical (`\n`-delimited) lines.
- Rows per cassette default to `VISIBLE_LINES` (5) and are configurable via the `-l` CLI flag or `visible_lines` in `~/.config/cassette/config.toml`, clamped to `MIN_VISIBLE_LINES..=MAX_VISIBLE_LINES`.
- Topic templates live in config.toml as `[templates]` entries (`morning = ["gratitude", "priorities"]`) and are selected with `-T <name>`.
- All rendering colors flow through the active `Theme` (resolved in `main.rs`, passed to `ui::render`); never hardcode colors in `ui.rs`. Themes come from config (`theme = "name"`, `[themes.<name>]` tables) or `--theme`; with explicit text+background colors the focused fade lerps between them (`themed_fade`), otherwise it falls back to the modifier-based fade.

## Planning and specs

Designs and implementation plans live in `docs/superpowers/specs/` as
`YYYY-MM-DD-<topic>-design.md`, created through the `superpowers` skills
(brainstorming -> writing-plans -> executing-plans). There is no external issue
tracker; the spec files are the durable record.

- Read the spec first and follow it — steps, file paths, and acceptance criteria were
  written against this repo. Verify claims about the code against the current source
  before acting; the code may have moved since the spec was written.
- Specs flag **human steps** (browser logins, tokens, pushes to external services).
  Don't attempt these — do the agent-executable parts, then tell the user exactly what
  remains.
- Check the acceptance criteria before calling work done, and say plainly what deviated
  or couldn't be verified.
- If a spec turns out to be wrong or stale, update it in the same change — the files are
  the durable record, not the session.
- Decompose work larger than ~500 lines into sequenced phases, each independently
  testable and each leaving the tool working.
- Promote durable decisions out of specs into real docs (`docs/distribution.md`, README).
  A spec is scaffolding, not documentation; git history is the archive.

`docs/plans/` holds older plan files from a retired tracker; they are named by issue
number and those issues no longer exist. Treat them as reference, not as live work.
